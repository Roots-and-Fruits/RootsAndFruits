# RootsAndFruits 리뉴얼 요구사항

이 문서는 프로젝트 생성 전 대화에서 합의한 내용을 정리한 기준 문서다. 최신 사용자 결정으로 바뀐 내용만 유지하며, 제안 또는 세부 확인이 필요한 내용은 마지막 절에 분리한다. 파일명, 테이블명, 라우트명은 별도로 확정하지 않는 한 구현 시 정할 수 있다.

## 1. 목적과 범위

- 체험농장 현장에서 손님이 태블릿 또는 QR로 접속한 개인 휴대폰으로 택배 상품을 주문한다.
- 접수 후 결제주문번호를 카운터에 제시한다. 사장님이 사이트에서 상품·총액을 확인하고 별도 POS에 입력해 결제한다.
- 사장님은 2명이며, 하루 주문은 수십 건에서 많으면 수백 건이다.
- 현재 운영 중이지 않고 새로 시작한다. 기존 주문·고객 데이터는 이전하지 않는다.
- `RootsAndFruits/`에 새로 구성한다. 별도 Spring 서버를 운영하지 않고 Next.js와 Supabase를 사용한다.
- Supabase 프로젝트는 새로 준비하며, 웹 배포 대상은 Vercel이다.
- 디자인은 기존과 무관하게 새로 설계한다. 기본 UI 라이브러리와 재사용 가능한 컴포넌트를 사용한다.
- 고객 화면 로고의 영문 브랜드 표기는 `TREE & BERRY`를 사용한다.
- 홈 상단 영문 문구는 `TREE & BERRY FARM`, 주제 문구는 `산지에서 갓 수확한 신선함 그대로, 농장에서 식탁으로 직배송!`을 사용한다. 최신 사용자 요청에 따라 ‘농장에서’로 오타를 수정했다.
- 브랜드 로고는 제공된 `assets/brand/logo.ai`의 귤 캐릭터를 SVG로 변환해 공통 헤더와 브라우저 아이콘에 적용한다. 헤더는 기존 한글·영문 브랜드명과 함께 표시하며 원본 벡터와 색상을 유지한다.
- 카카오톡 등 링크 공유 시 브랜드 로고를 담은 대표 이미지·제목·설명을 표시한다. 기준 도메인은 사용자가 지정한 `https://www.2180.co.kr/`이며 상품 구매와 체험 과일 보내기를 함께 안내한다.
- 모바일 홈은 상단 소개 영역과 선택 카드의 높이·간격을 줄여 첫 화면에서 상품 구매·체험 과일 보내기 두 선택지가 함께 보이도록 한다. 선택 카드는 아이콘·제목·설명·진입 안내를 간결하게 배치하고 전체 영역을 누를 수 있게 한다. 태블릿·데스크톱의 소개 영역과 카드 배치는 유지한다.
- 홈의 두 선택 카드는 설명 영역에 두 줄 높이를 확보해 한 줄·두 줄 설명의 카드 높이와 진입 안내 위치를 맞춘다.
- 명시적으로 변경한 사항 외에는 기존 프로젝트의 업무 흐름을 기준으로 한다. 기존 소스 구조나 명칭의 복제는 요구하지 않는다.

## 2. 계정과 접근

### 고객 회원과 비회원

- 개인 고객은 카카오 로그인 또는 비회원 주문을 이용한다. 고객용 ID·비밀번호 로그인/가입은 제공하지 않는다.
- 개인 회원 기능은 자신의 주문 내역·배송 상태 조회와 배송지 저장이다.
- 고객의 접수 후 주문 내용 수정·취소 기능은 제공하지 않는다.
- 비회원의 별도 주문 조회는 제공하지 않는다. 접수 완료 시 번호를 안내하고 이후 문의는 카운터에서 처리한다.

### 현장 태블릿 회원

- 태블릿은 Supabase Auth의 전용 회원 계정으로 미리 로그인해 놓는다. 태블릿마다 별도 ID·비밀번호를 사전 발급하고 `/tablet-login`에서 로그인한다. 고객 화면에는 전용 로그인 링크를 노출하지 않는다. 관리자 계정과 권한을 분리하며 별도 기기 인증 시스템을 만들지 않는다.
- 이 주문은 전용 회원 계정에 연결되는 회원 주문이다. 손님은 로그인 절차 없이 로그인된 기기로 주문한다.
- 주문에 연결되는 회원과 손님이 입력하는 보내는 사람 정보는 별개다. 회원 프로필로 보내는 사람을 덮어쓰지 않는다.
- 개인 휴대폰 회원 주문과 태블릿 주문은 같은 주문 화면과 동작을 사용한다.
- 현장 태블릿에서 접수됐는지 구분할 수 있도록 전용 계정 식별 정보를 남긴다. 구체적인 필드명은 구현 시 결정한다.
- 태블릿 회원은 관리자 계정이 아니며 카운터·관리자 기능에 접근할 수 없다.

### 관리자

- 고객 화면에는 관리자 진입 링크를 표시하지 않는다. 관리자는 `/namu-admin` 주소를 직접 입력하거나 북마크로 접속한다. 기존 `/admin` 주소는 새 주소로 연결하지 않으며, 관리자 인증과 서버·DB 권한 검사는 유지한다.

- 관리자 화면은 데스크톱 사용을 기본으로 입력창·버튼·간격을 간결하게 구성하고 폼과 검색 조건을 여러 열로 배치한다. 작은 화면에서는 터치 조작에 맞는 크기와 세로 배치를 유지한다. 고객 주문 화면의 크기·배치에는 적용하지 않는다.
- 카운터·주문 관리는 결제주문당 한 행, 발송 관리는 배송지당 한 행인 세로 목록으로 표시한다. 최신 접수 주문(주문번호 내림차순)을 위에 두며 데스크톱은 열 제목과 항목을 맞추고 작은 화면은 한 주문의 정보를 여러 줄로 배치한다. 주문 관리에는 배송지별 발송 상태의 건수를 요약한다.
- 목록의 결제 상태·방식은 `결제 완료 · 카드`처럼 한 줄로 표시한다. 재접수 태그와 메모도 공간이 허용하면 가로로 이어서 배치하고 행의 상하 여백을 줄인다. 긴 메모는 줄바꿈하며 작은 화면의 버튼·체크박스 터치 영역은 유지한다.
- 카운터 목록은 보내는 분 영역을 줄이고 옆에 주문 당시 상품명·합산 수량을 표시한다. 같은 상품이 여러 배송지에 있으면 합산하며 체험상품에는 이전 데이터의 임시 과일·중량 접두어를 표시하지 않는다. 작은 화면에서는 상품 정보를 별도 줄로 표시한다.
- 사장님용 관리자 계정 2개만 카운터와 관리자 페이지에 접근한다.
- 관리자 로그인은 고객 카카오 로그인과 구분된 ID·비밀번호 로그인이다. 관리자에게 카카오 가입을 요구하지 않는다.
- 로그인 화면을 분리하는 것에 그치지 않고 서버 및 DB 접근 권한도 분리한다.
- 관리자 계정을 사전에 준비한다. 고객의 카카오 로그인이나 일반 회원가입으로 관리자 권한을 얻을 수 없어야 한다.

## 3. 결제주문과 배송주문

```text
결제주문 1건: 계속 증가하는 결제주문번호, 주문자, 합산 금액, 결제 상태
  ├─ 배송주문 A: 수령인·주소·배송 일정·발송 상태
  │    └─ 상품 항목: 상품·단가·수량
  └─ 배송주문 B: 수령인·주소·배송 일정·발송 상태
       └─ 상품 항목: 상품·단가·수량
```

- 한 사람이 여러 배송지로 서로 다른 상품을 보낼 수 있다.
- 고객이 카운터에 제시하고 한 번에 결제하는 번호는 하나다.
- 배송지별 주문은 별도로 저장하고 배송·엑셀 작업에서 개별적으로 처리한다.
- 결제주문번호는 날짜마다 초기화하지 않고 계속 증가한다.
- 운영 전 테스트 데이터 초기화는 주문·문자와 연결된 배송·상품 항목·출력 기록·주문 관련 이력만 정리한다. 최신 사용자 요청에 따라 주문번호 시퀀스는 초기화하지 않으며 상품·설정·계정은 유지한다. 현재 재고 관리 상품이 없어 재고 수량은 변경하지 않는다.
- 저장 배송지나 상품 정보를 수정하더라도 이미 접수한 주문의 주소·상품·단가는 유지한다.

## 4. 고객 주문 흐름과 초기화

```text
일반 / 체험 진입
→ 보내는 사람 입력
→ 받는 사람·주소 입력
→ 해당 배송지의 상품·수량 선택
→ 배송 일정 처리(일반/체험의 기존 차이 유지)
→ 다른 배송지 추가 시 받는 사람 입력부터 반복
→ 전체 주문 확인
→ 접수
→ 결제주문번호·총액·카운터 결제 안내
```

- 접수 전 입력 내용은 수정할 수 있다. 이전 단계로 돌아가면 작성 내용을 유지한다.
- 새로고침·화면 이탈로 작성 내용이 사라지지 않도록 브라우저 로컬스토리지에 임시 저장한다. 새로고침·주문 주소 직접 재진입은 자동 복원하며, 홈의 주문 버튼으로 재진입할 때는 아래 선택을 제공한다. 다음 버튼을 누르기 전의 미완성 입력, 현재 단계, 추가 중인 배송지와 통합 수정 중인 내용도 포함한다. 전화번호 원문은 임시 저장 과정에서 정리하지 않는다.
- 최신 사용자 결정: 계정 종류를 구분하지 않고 개인 회원·태블릿 회원·비회원 모두 홈에서 선택한 주문 종류에 작성 내용이 있으면 ‘작성 중인 주문이 있어요’ 모달로 ‘이어 작성하기 / 처음부터’를 묻는다. 작성 내용이 없으면 바로 시작한다. 선택 전에는 이전 개인정보를 표시하지 않으며 닫으면 내용을 유지하고 홈으로 돌아간다. 일반/체험과 실제/미리보기의 임시 저장은 별도로 유지한다. 결과를 확인하지 못한 접수 요청이 있으면 초기화 선택 대신 기존 접수 결과 확인 흐름을 사용해 중복 접수를 방지한다.
- 주문 화면은 CSS로 세로 방향 당겨서 새로고침을 억제한다. 브라우저별 지원 차이가 있으므로 입력 보존은 임시 저장·복원으로 처리하고, 일반 스크롤은 유지한다. 저장소 사용이 차단되면 사용자에게 안내한다.
- 주문 중 헤더의 주문 안내는 화면을 이동하지 않는 모달로 제공한다. 닫으면 작성하던 입력과 단계로 돌아온다. 홈의 주문 안내 페이지는 유지한다.
- 임시 저장에 시간에 따른 자동 초기화를 추가하지 않는다. ‘처음부터’ 초기화는 현재 주문의 임시 저장·수정 중 내용·추가 중 배송지를 함께 지우고 로그인 데이터는 유지한다. 공용 기기 안내를 제공한다.
- 최종 확인의 수정 버튼은 단계형 입력으로 되돌아가지 않고 별도의 통합 수정 화면을 연다. 보내는 분과 모든 배송지의 수령인·주소·상품·배송 일정을 한 페이지에서 수정하고, 수정 완료 시 최종 확인으로 바로 돌아온다. 체험은 기존처럼 날짜 선택을 제공하지 않는다.
- 최종 확인에서 배송지를 추가한 뒤 받는 사람 단계의 이전 버튼을 누르면 최종 확인으로 돌아간다.
- 보내는 분과 받는 분의 휴대폰은 입력 중 `010-1234-5678` 형태로 하이픈을 자동 표시한다(통합 수정·복원·보내는 사람과 같음 포함). 최신 사용자 피드백에 따라 숫자와 하이픈으로 된 입력의 표시 방식을 변경한다. 텍스트 대치로 들어온 공백·문자와 조합 중 입력은 원문을 유지하며, 숫자 키패드를 유지한다. 다음 단계 또는 수정 완료 시 공백·하이픈 등 숫자 외 문자를 제거한 결과를 11자리로 검증하고 주문 입력에 반영한다. 자릿수가 맞지 않는 번호를 임의로 자르지 않는다.
- 받는 분의 ‘보내는 사람과 같아요’ 선택 시 자동 입력된 필드가 수정 불가 상태임을 배경·테두리·안내 문구로 명확하게 표시한다.
- 주소 검색 버튼과 우편번호 필드 모두 검색창을 연다. 우편번호 필드는 키보드 Enter·Space도 지원한다.
- 휴대폰 등 좁은 화면에서는 상단의 현재 단계·전체 단계 수와 얇은 진행 막대로 입력 영역의 공간을 확보한다. 태블릿 등 넓은 화면에서는 확대된 단계 원과 숫자를 유지한다.
- 주문 화면의 이전·다음 버튼은 화면 크기 및 스크롤 위치와 관계없이 화면 하단에 고정한다. 버튼 영역 때문에 마지막 내용과 입력 요소가 가려지지 않도록 여백을 확보한다. 통합 수정의 취소·수정 완료에도 같은 고정 영역을 적용한다.
- 개인정보 필수 동의와 마케팅 선택 동의는 모두 미선택으로 시작한다. ‘전체 동의 (선택 포함)’와 개별 체크를 함께 제공하며 서로 상태를 연동한다. 선택 동의를 거절해도 주문할 수 있다. 이는 미리보기 피드백에 대한 사용자의 명시적 선택이다.
- 일반 상품과 체험 상품은 고객이 혼동하지 않도록 별도 목록과 진입 흐름으로 유지한다. 상품 구매는 주황색, 체험 과일 보내기는 초록색 계열로 메인 선택 카드·주문 종류 배지·진행 단계·주요 버튼·완료 화면에 일관되게 적용한다. 색상뿐 아니라 이름과 아이콘도 함께 표시한다.
- 일반 전용 링크는 일반, 체험 전용 링크는 체험으로 시작한다. 공통 홈에서는 두 메뉴를 제공한다.
- ‘다음 주문 시작’ 버튼은 해당 주문 종류의 진입 화면으로 돌아간다. 주문 완료 후 자동 이동은 메인(`/`)으로 향한다.
- 작성 중 입력 초기화는 버튼으로만 처리한다. 최신 사용자 결정으로 주문 완료 화면은 일정 시간 후 메인 화면으로 자동 이동한다. 시간은 구현에 위임되어 계좌정보를 확인할 수 있도록 60초로 정했으며 남은 시간을 표시한다. 접수 결과가 있는 경우에만 타이머를 시작하고 다른 화면으로 나가면 해제한다. 자동 이동 시 완료 결과를 정리하고 로그인 상태는 유지한다.
- 초기화는 현재 주문 입력을 정리하며 회원 로그인은 유지한다. 실제로 접수한 주문을 삭제하는 동작이 아니다.
- 초기화 후 이전 고객의 입력 정보가 뒤로 가기나 남은 폼 상태로 복원되지 않도록 한다.

## 5. 상품 관리와 선택 화면

| 항목 | 요구사항 |
| --- | --- |
| 일반/체험 | 서로 구분해 관리하고 각 주문 흐름에 맞게 노출 |
| 과일 종류 | 일반상품만 사용. 감귤·한라봉 등 상품 이름에서 분리 |
| 중량 | 일반상품만 사용. kg 단위로 입력하며 소수 중량도 지원 |
| 상품 내용 | 자유 입력. 체험상품에서는 상품을 식별하는 이름으로 사용하므로 필수 |
| 가격 | 원 단위, 배송비 포함 |
| 재고 관리 여부 | 일반상품별 설정, 기본은 미사용. 체험상품은 사용하지 않음 |
| 재고 수량 | 일반상품의 재고 관리 시 판매 단위인 박스·개수로 관리 |

- 체험상품은 구분(일반/체험)·내용·가격·판매 중 여부만 관리한다. 과일·중량·재고 관리·묶음 할인 항목은 입력·목록·고객 선택 화면에서 제공하지 않으며 API와 DB에서도 사용을 제한한다. 체험상품은 내용으로 표시하며 과일 그룹 없이 상품 단위로 순서를 변경한다.
- 기존 주문의 저장 기록은 새 형식으로 수정하지 않는다. 최신 사용자 요청에 따라 카운터·주문 상세·발송 목록과 새 엑셀에서는 체험상품의 이전 과일·중량 접두어를 숨기고 주문 당시 내용·수량으로 표시한다. 일반상품의 과일·중량은 유지한다. 현재 상품 내용으로 과거 주문명을 덮어쓰지 않는다.
- 새 상품 등록 시 ‘판매 중’은 기본 선택 상태다. 기존 상품 수정 시에는 저장된 판매 상태를 유지한다.
- 재고 수량 입력은 ‘재고 관리’를 켰을 때만 표시한다. 끈 상태로 저장하면 기존 재고 수량을 유지한다.
- 일반상품 선택 화면은 과일별로 묶은 목록이며 중량·내용·가격과 수량 버튼을 표시한다. 체험상품은 내용·가격과 수량 버튼을 표시한다.
- 상품 선택 행은 상하 여백을 줄여 간결하게 표시한다. 상품 정보와 수량 버튼은 좌우로 배치하고 가격·할인 표시는 가능한 한 같은 줄에 둔다. 긴 상품 설명은 줄바꿈하며 수량 버튼은 터치하기 편한 크기를 유지한다.
- 상품 사진과 사진 등록 기능은 이번 범위에서 제외한다.
- 수량은 `− / +` 방식으로 선택하며 해당 배송지의 상품 수량과 금액 합계를 확인한다.
- 배송지마다 직접 선택한다. 이전 배송지 상품 복사 버튼이나 자동 채움은 제공하지 않는다.
- 새 배송지의 상품 수량은 0부터 시작한다. 이미 작성한 배송지로 돌아가면 그 선택은 유지한다.
- 상품은 하나 이상 선택해야 다음 단계로 진행한다.
- 상품 관리 목록은 일반·체험을 나눈 일렬 리스트다. 일반상품은 과일 그룹 순서와 같은 과일 안의 상품 순서를, 체험상품은 상품 순서를 손잡이 드래그로 변경하고 ‘순서 저장’으로 일괄 반영한다. ‘순서 취소’는 저장 전 변경을 되돌린다. 위·아래 이동 버튼과 숫자형 노출 순서 입력은 제공하지 않는다.
- 새 일반상품은 기존 과일 그룹 맨 뒤에 추가하며, 새로운 과일 그룹은 목록 맨 뒤에 추가한다. 체험상품은 목록 맨 뒤에 추가한다. 구분·과일 종류 변경 시에도 대상 목록·그룹 맨 뒤로 이동한다. 가격·내용 등 일반 수정으로 순서를 바꾸지 않는다.
- 일반상품 목록에는 상품명·중량·내용, 가격, 판매 상태, 재고, 할인 대상 여부와 수정 버튼을 표시한다. 체험상품 목록에는 내용·가격·판매 상태와 수정 버튼을 표시한다. 판매 중지 상품도 정렬 목록에 포함하며 삭제 상품은 숨긴다.
- 정렬 저장 중 일부 상품만 반영되지 않도록 한 번에 저장한다. 다른 관리자가 순서나 그룹을 바꾸거나 상품을 추가·삭제한 경우 오래된 목록으로 덮어쓰지 않고 새로고침을 안내한다.
- 과일 종류 목록 편집 방식, 중량 허용값 등 세부 입력 제약은 기존 사실과 사용 맥락을 확인해 정한다. 3kg·5kg만 허용한다고 단정하지 않는다.

## 6. 가격과 재고

### 금액

- 상품 가격에 배송비가 포함된다. 별도 배송비를 더하지 않는다.
- 일반상품별 묶음 할인 대상 여부를 설정한다. 기본은 끔이며 일반상품 공통의 할인 금액을 관리자 설정에서 관리한다. 초기 금액은 0원이다. 체험상품은 묶음 할인을 적용하지 않으며 관련 안내도 표시하지 않는다.
- 각 배송지에서 대상 상품 종류에 관계없이 수량을 합산하여 `floor(대상 수량 / 2) × 공통 할인 금액`을 할인한다. 3개는 1회, 4개는 2회 할인한다.
- 여러 배송지가 있는 결제주문도 배송지별로 각각 계산한다. 다른 배송지의 수량을 합치거나 같은 주소의 별도 배송주문을 자동 병합하지 않는다.
- 할인액은 해당 배송지의 대상 상품 금액 합계를 넘지 않는다. 비대상 상품 가격은 할인하지 않는다.
- 실제 발송은 상품별로 하므로 할인으로 송장 수량을 줄이지 않는다. 할인은 상품 항목으로 저장하지 않는다.
- 선택 시점의 가격·할인 조건을 보관하는 기능은 만들지 않는다. 관리자는 매장 마감 후 설정을 변경하며, 화면은 조회한 값·실제 접수는 서버에서 조회한 값으로 계산한다. 접수된 주문에는 당시 상품·가격·할인 정보를 보존한다.
- 각 배송주문의 결제금액은 상품 단가 × 수량 합계에서 묶음 할인을 뺀 값이며, 결제주문의 금액은 모든 배송주문의 결제금액 합계다.
- 카운터의 상품 합산은 판매 상품의 식별자를 기준으로 한다. 과일이 같아도 중량·내용 등이 다른 상품은 구분한다.

### 재고

- 일반상품은 재고 미사용이 기본이다. 체험상품은 항상 재고를 관리하지 않는다. 미사용 상품에는 재고 수량에 따른 판매 제한·차감을 적용하지 않는다.
- 사용 상품은 주문 접수 때 차감한다. 결제 완료 때 추가 차감하지 않는다.
- 선택 중 예약, 재고 선점, 예약 만료 타이머는 구현하지 않는다.
- 선택 시 주문 가능했던 상품은 접수 직전에 재고가 부족해져도 주문을 허용한다. 재고 50개에 51개·52개가 판매되는 정도의 초과 판매를 감수한다.
- 이미 품절인 상품의 새 선택은 제한하되, 앞서 선택한 상품을 최종 접수에서 일괄 거절하는 엄격한 재고 정책을 도입하지 않는다.
- 초과 판매 수량을 잃지 않도록 음수 잔량으로 기록하고 관리자에게 부족 수량을 보여주는 것을 설계 기본안으로 한다.
- 초과 판매의 빨간 경고 글자는 재고 관리가 켜져 있고 수량이 음수인 상품에만 적용한다. 재고 관리를 끄면 일반 글자색으로 표시하되 기존 수량·이력은 보존한다.
- 미결제 접수도 차감 상태를 유지하며 자동 취소하지 않는다. 관리자가 엑셀 출력 전 주문을 전체 취소하면 결제 여부와 관계없이 해당 주문에서 실제 차감한 재고만 반환한다.
- 동시 요청으로 재고 변경이 유실되거나, 중복 요청으로 재고가 중복 차감·반환되지 않도록 한다.
- 취소는 현재 재고 관리 여부가 아니라 원래 주문에서 실제 차감한 기록에 따라 반환한다. 재고 관리를 꺼도 수량과 변경 이력을 보존하며 관리자 수량 조정은 별도 기록한다.

## 7. 카운터와 결제 상태

```text
관리자 로그인
→ 주문번호 검색 / 최근 주문 선택
→ 상품별 합산 수량·총액 확인
→ 별도 POS에 입력하고 실제 결제
→ 사이트에 결제 완료 기록
```

- 온라인 PG 승인, 자동 POS 연동, 사이트에서의 자동 환불은 현재 범위가 아니다.
- 사이트의 결제 상태 변경이 실제 POS 승인·환불을 실행한다고 표시하지 않는다.
- 두 관리자가 같은 주문을 처리하거나 재시도해도 결제 기록의 효과가 중복되지 않도록 한다.
- 처리 상태와 시각, 처리 관리자를 추적할 수 있도록 구성한다.
- 결제 완료 확인창에서 카드·현금·입금·기타 중 정확히 하나를 선택한다. 초기에는 미선택이며 선택해야 완료할 수 있다. 기타의 별도 입력창은 만들지 않고 필요하면 기존 메모를 활용한다.
- 결제 방식은 결제주문 단위로 결제 상태·완료 시각과 함께 저장하고 카운터·관리자 목록과 주문 상세에 표시한다. 여러 배송지여도 결제 방식은 한 번만 선택한다.
- 같은 주문에 대한 반복·동시 결제 요청은 최초 기록한 결제 방식·시각·처리 이력을 덮어쓰거나 중복 생성하지 않는다. 기존 결제 완료 주문의 방식은 추측해 채우지 않고 미기록으로 유지한다.
- 주문 완료 페이지의 카운터 결제 안내 아래에 계좌송금 안내를 제공한다. 사용자 지정 계좌는 농협 `2180-2180-2180-9`, 예금주는 `제주체험종장`이며 입력된 표기를 그대로 사용한다. 송금 후 카운터에 알리도록 안내하며 결제 완료 기록은 기존 관리자 처리로 유지한다.

## 8. 주문 불변성, 취소, 재접수

### 주문서 인쇄

- 사용자 요청: 카운터·주문 관리에 영수증 프린터용 주문서 인쇄 버튼을 제공한다. 발송 관리·고객 주문 화면에는 제공하지 않는다.
- 대상 프린터는 사용자가 알려준 SEWOO SLK-TS100이다. 제조사 규격은 80mm 감열지, 실제 인쇄 폭 72mm이며 해당 폭에 맞춘 흑백 주문서 미리보기를 제공한다.
- 구현 방식: 목록·상세의 ‘주문서’ 버튼으로 관리자 전용 새 창을 열고 저장된 최신 주문을 조회한 후 브라우저 인쇄창에서 프린터를 선택한다. 주문번호·접수 시각·구분·결제 상태/방식·보내는 분·상품별 단가/수량/금액·할인/합계·배송지별 받는 분/주소/출발 날짜/상품/메모를 표시한다. 주문 당시 상품/금액을 사용하며 취소 주문과 재접수는 표시를 유지한다.
- 주문서 인쇄는 조회 기능이다. 결제·취소·택배 엑셀 출력·발송 상태나 이력을 변경하지 않는다. 인쇄만으로 주문 취소가 차단되지 않는다. 별도 DB 변경이나 인쇄 횟수 기록은 추가하지 않는다.
- 실제 용지 길이·자동 절단은 설치된 프린터 드라이버 설정에 따른다. 인쇄창 없이 자동 출력하는 장치 직접 제어는 이번 구현에 포함하지 않는다. 설정 절차는 [주문서 인쇄 안내](receipt-printing.md)를 참고한다.

### 주문 취소와 재접수

- 관리자 버튼은 ‘주문 취소’, ‘주문 재접수’로 표시한다. 배송지가 여러 개여도 한 주문으로 관리하므로 버튼에 ‘전체’를 붙이지 않는다. 처리 범위는 해당 결제주문에 포함된 모든 배송지다.

- 접수된 주문의 보내는 사람, 받는 사람, 주소, 상품, 수량, 배송 일정 등을 고객이나 관리자가 직접 수정할 수 없다.
- 결제·취소·출력·발송 등 운영 상태 변경은 가능하다. 기존 운영 메모는 접수 내용과 분리해 기존 흐름을 확인한다.
- 최신 사용자 결정: 접수·결제 완료 주문 모두 모든 배송지가 엑셀 출력 전이면 관리자가 주문 전체를 취소할 수 있다. 한 배송지라도 출력 이력이 있거나 발송 완료 상태이면 주문 전체 취소를 막는다. 엑셀 출력은 파일 생성·출력 묶음 저장 성공을 기준으로 하며 실제 다운로드 완료 여부를 기준으로 하지 않는다.
- 결제 후 취소해도 기존 결제 방식·결제 시각·주문 금액·주문번호·상품/배송지 기록은 보존하고 취소 상태·시각·처리자 이력을 남긴다. 취소 주문은 발송 대상에서 제외한다. POS 결제 취소·환불은 운영자가 외부에서 처리하며 별도의 환불 상태·금액 입력이나 연동은 추가하지 않는다. 부분 취소는 제공하지 않는다.
- 취소 재시도로 재고·이력이 중복 반영되지 않는다. 결제·취소·엑셀 출력은 같은 주문의 잠금 순서를 맞춰 순서대로 처리한다. 출력이 먼저 확정되면 취소가 실패하고, 취소가 먼저 확정되면 출력이 실패한다. 이전 화면에서 취소를 요청해도 DB가 출력 여부를 다시 확인하며 실패 이유는 확인창에서 보여준다.
- 관리자 재접수는 결제주문 전체의 입력 내용을 복사한다. 일부 배송주문만 골라 복사하는 기능은 범위에 없다.
- 복사한 입력은 새로 접수하기 전 수정할 수 있다.
- 금액은 현재 상품 가격으로 계산한다. 이전 단가를 유지하거나 임의 단가를 입력하는 기능은 포함하지 않는다.
- 최종 재접수 시 새로운 결제주문번호와 배송주문들을 생성한다. 원본 주문은 유지한다.
- 재접수와 원본 취소는 독립이다. 원본 취소를 선행 조건으로 강제하거나 새 접수와 함께 자동 취소하지 않는다.
- 재접수 화면에 원본이 자동 취소되지 않는다는 사실을 안내한다.
- 원본 주문과 재접수 주문의 관계를 기록한다.
- 재접수 건은 메모 영역에 원본 주문번호와 함께 표시하고, 카운터·주문 관리·발송 목록에서 상세를 열지 않고 재접수 여부와 운영 메모를 확인할 수 있게 한다. 배송지가 여러 개면 카운터·주문 관리에서 메모에 배송지 번호·수령인을 함께 표시한다.
- 표시 구현: 저장된 원본 주문 연결 정보로 재접수 안내를 자동 표시하며 운영자가 수정하는 메모 문자열에는 삽입하지 않는다. 메모를 수정하거나 지워도 재접수 표시는 유지한다.
- 빈 메모는 목록에서 안내 문구나 빈 영역 없이 숨긴다. 재접수 태그는 메모가 없어도 표시한다. 발송 관리의 상세 진입 버튼은 ‘상세’로 표시한다.
- 목록의 메모 본문은 굵고 진한 글자로 강조해 배송지 안내·주소와 구분되게 한다. 기존 글자 크기와 행 간격은 유지한다.
- 결제 완료·발송 완료 상태를 복사하지 않는다. 새 주문은 미결제·미발송 상태이며 최종 접수 때 재고를 처리한다.
- 재접수에서 현재 판매 중지·삭제·품절 상품은 교체·제거해야 한다. 선택 가능 범위를 벗어난 예약일은 다시 확인한다. 일반 배송은 접수일 기준으로 계산한다. 고객 회원 연결은 회원 인증 도입 때 별도로 정한다.

## 9. 배송 날짜: 기존 동작 유지

다음은 기존 소스에서 확인한 동작이다. 화면의 ‘배송’ 표현만 보고 발송일 또는 수령일로 단정하지 않는다.

| 구분 | 기존 요청 날짜 | 기존 서버 저장 |
| --- | --- | --- |
| 일반 상품의 일반 배송 | 오늘부터 2일 뒤 | 요청 날짜에서 하루 차감 |
| 일반 상품의 예약 배송 | 오늘부터 3일 뒤부터 관리자 설정 기간까지 선택, 일요일 제외 | 선택 날짜에서 하루 차감 |
| 체험 상품 | 별도 날짜 선택 없이 상품 단계에서 오늘부터 2일 뒤 설정 | 요청 날짜에서 하루 차감 |

- 예약 최대 범위는 서버 설정을 사용하며 기존 캘린더의 값 부재 시 기본값은 14일이다.
- 예약 배송일은 라이브러리 기반 공통 datepicker로 선택한다. 한국어 달력과 ‘날짜를 선택해주세요’ 안내를 제공하며, 일요일과 예약 가능 기간 밖의 날짜는 선택 불가 상태로 표시한다. 고객 주문·통합 수정·관리자 재접수에서 같은 컴포넌트를 사용하고 화면 크기에 맞춰 너비를 제한한다.
- 일요일 선택 금지는 예약 캘린더의 기존 규칙이다. 일반·체험 기본 날짜에도 자동 적용한다고 확대 해석하지 않는다.
- 새 저장 구조에서 요청 날짜와 관리자 처리 날짜를 구분하더라도 기존 계산 결과는 유지한다.
- 한국 현장 운영 기준으로 날짜를 처리한다. 날짜를 UTC 변환하면서 하루가 달라지지 않도록 검증한다.
- 관리자 날짜 범위 설정 기능을 유지한다.

## 10. 엑셀 출력과 발송 관리

- 택배사 API 직접 연동과 송장번호 업로드를 이번 범위에 추가하지 않는다. 엑셀 출력 후 기존 택배 프로그램에서 송장 업무를 처리한다.
- 결제주문 단위로 보는 카운터와 달리 배송 목록은 배송주문별로 처리한다.
- 단순 다운로드 버튼만 제공하지 않고, 어떤 배송주문들을 출력했는지 출력 묶음과 상태를 저장한다.
- 화면 흐름: 출력 대기 → 엑셀 출력됨·발송 대기 → 발송 완료.
- 결제 대기·취소 주문이 출고 대상으로 잘못 포함되지 않도록 한다.
- 출력 묶음에는 포함된 배송주문, 생성 시각, 생성 관리자, 파일을 식별할 정보를 보관한다.
- 출력 묶음을 확인하고 해당 주문들을 한 번에 발송 완료 처리할 수 있어야 한다.
- 이미 출력된 주문은 기본 출력 대기 목록에서 제외한다.
- 브라우저의 실제 저장 완료를 완전히 확인할 수 있다고 가정하지 않는다. ‘엑셀 출력됨’은 파일 생성 성공을 기준으로 기록하고 재다운로드 경로를 제공한다.
- 파일 생성 실패를 성공 상태로 기록하지 않는다.
- 기본안: 같은 묶음 재다운로드는 같은 파일을 제공하고 새로운 출고 대상을 중복 생성하지 않는다.
- 기본안: 묶음에서 개별 배송주문도 선택해 발송 처리할 수 있고, 취소된 주문은 발송 완료 대상에서 제외한다.
- 구체적인 택배 엑셀 열·정렬·값 형식은 기존 `OrderTable.tsx`의 출력 형식을 먼저 확인한다. 이전 묶음 배송 할인에 의존한 수량 계산은 그대로 옮기지 않는다.

## 주문 안내 문자 (최신 사용자 결정)

- 알리고 로그인과 별개로 SOLAPI 문자 발송을 연동한다. 추후 알리고 알림톡으로 바꿀 수 있도록 공급자 통신과 주문 알림 처리를 분리한다.
- 주문접수·주문발송 안내의 수신자는 모두 주문에 입력된 **보내는 분**이다. 받는 분에게 보내지 않는다.
- 구현 방식: 접수 성공 시 결제주문당 1회, 각 배송지의 실제 발송 완료 시 배송지당 1회. 결제 전 접수임을 문구에 명시하고 엑셀 출력 시에는 보내지 않는다. 재접수는 새 주문 안내를 보낸다.
- 중복 요청으로 중복 발송하지 않도록 DB에 알림 작업을 저장한다. 공급자 접수와 실제 휴대폰 수신 성공을 구분하며 통신 오류로 결과가 불확실한 건은 무조건 재발송하지 않는다.
- 기본은 꺼짐이며 실제 계정·발신번호·키 설정 후 관리자에서 켠다. 이전 주문 소급 발송은 하지 않는다. 문구·발송 내역·실패 재시도와 설정 절차는 `docs/sms-setup.md`를 기준으로 한다.

## 11. 이번 범위에서 제외하는 기능

- 별도 Spring 백엔드 및 기존 데이터 이전.
- 고객 주문 내용 수정·취소, 관리자 접수 내용 직접 수정, 부분 취소.
- 비회원의 주문번호 기반 공개 주문 조회.
- 태블릿을 비회원 접수로 저장하는 별도 주문 시스템.
- 주문 작성 중 자동 초기화 타이머. 완료 화면의 60초 후 메인 이동은 제공한다.
- 재고 선택 시 예약, 예약 만료, 접수 시점 부족을 이유로 한 엄격한 재고 차단.
- 별도 배송비, 상품 사진, 배송지 간 상품 복사와 자동 채움.
- 개인 회원의 주문 내역·저장 배송지 화면은 로그인 연동 후 후속 구현한다. 이번 단계에는 카카오 인증·태블릿 인증 및 접수 시 회원 연결을 포함한다.
- 온라인 PG·POS 자동 연동, 택배사 송장 발급 API.
- 데이터 모델·명칭·UI를 기존 프로젝트와 동일하게 복제하는 제약.

## 12. 제안 또는 구현 직전 확인할 세부 사항

아래는 추가 기능 도입 지시가 아니다. 관련 구현에 도달했을 때 기존 코드와 사용자 의도를 확인하고 확정한다. 이 목록 때문에 독립적인 프로젝트 기반 작업을 중단하지 않는다.

- **공용 회원 계정의 주문 내역·저장 배송지:** 주문 흐름은 개인 회원과 동일하다. 여러 손님이 쓰는 전용 계정의 회원 페이지 노출·접근 범위는 개인정보가 섞이지 않도록 확인한다. 무단으로 태블릿 전용 주문 흐름을 만들거나 비회원으로 전환하지 않는다.
- **가격:** 현재 조회값 적용으로 확정했다(6절). 가격 고정·견적 보관·시점별 조건 추적은 추가하지 않는다.
- **재접수 회원 연결:** 상품 교체·날짜 재확인은 확정했다. 원본 회원과 새 주문의 연결은 회원 인증 단계에서 확인한다.
- **반품·부분 취소:** 별도 요구사항이 정해지기 전에는 구현하지 않는다. 실제 POS 결제 취소·환불은 사이트 밖에서 처리한다.
- **출력 후 취소:** 최신 사용자 결정에 따라 허용하지 않는다. 결제 완료 여부와 무관하게 주문의 모든 배송지가 엑셀 출력 전일 때만 전체 취소한다.
- **출력 형식:** 기존 열 순서·형식을 유지한다. 할인 항목을 제외한 실제 상품·수량을 출력하고 발송지 우편번호·주소는 관리자 설정으로 관리한다. 사업장 실제 값은 운영 준비 시 입력한다.
- **외부 설정:** Supabase·카카오·Vercel·도메인·주소 검색 서비스 설정, 관리자 및 전용 회원 계정의 실제 ID와 발급 절차는 연동 단계에 준비한다. 비밀값을 이 문서에 적지 않는다.
- **디자인:** 기존과 무관한 새 시안이 필요하다. 라이브러리 선택을 최종 디자인 승인으로 간주하지 않는다.

## 13. 핵심 수용 시나리오

1. 일반·체험 각각 기존 순서로 접수하며, 보내는 사람 한 명과 여러 받는 사람을 입력할 수 있다.
2. 배송지마다 상품을 따로 담고, 배송주문은 나뉘지만 결제주문번호와 합산 결제는 하나다.
3. 개인 회원·태블릿 전용 회원은 같은 주문 기능을 사용하며 회원 ID가 올바르게 연결된다. 비회원만 회원 연결 없이 접수한다.
4. 고객과 태블릿 계정은 관리자 페이지와 관리자 데이터 처리에 접근하지 못한다.
5. 작성 중 기다려도 입력이 자동 초기화되지 않는다. 완료 화면은 60초 후 메인으로 이동하고 완료 결과를 정리한다. 수동 초기화와 자동 이동 모두 로그인은 유지한다.
6. 일반상품은 과일별 텍스트 목록이며 대상 상품에 배송지별 묶음 할인을 적용한다. 체험상품은 내용·가격 중심의 목록이며 재고·묶음 할인 없이 주문한다. 둘 다 별도 배송비가 없고 다음 배송지의 선택은 비어 있다.
7. 재고 미사용 상품은 재고 때문에 막히지 않는다. 사용 상품도 선택 이후 소진됐다면 접수되며 초과 판매가 기록된다.
8. 같은 접수 요청을 재시도해도 주문번호·주문·재고 효과가 중복되지 않는다.
9. 접수 내용은 고객·관리자 모두 직접 수정할 수 없다. 재접수는 전체를 복사하고 현재 가격으로 새 번호를 만들며 원본을 자동 취소하지 않는다.
10. 접수·결제 완료 모두 엑셀 출력 전 주문 전체 취소를 제공하며 일부라도 출력된 주문은 취소하지 못한다. 반복 취소로 재고가 중복 반환되지 않고 취소와 출력이 동시에 성공하지 않는다. 사이트 상태 변경이 실제 POS 작업을 실행하지 않는다.
11. 일반·체험 날짜 처리와 예약 가능 범위는 기존 소스의 동작과 일치한다.
12. 엑셀 출력 묶음에서 포함 주문을 추적하고 묶음 발송 완료를 처리할 수 있다. 출력 실패·재다운로드가 중복 발송 대상을 만들지 않는다.

## 14. 관리자 실제 연동 단계

- 화면: 카운터 / 주문 관리 / 발송 관리 / 상품·재고 / 설정.
- 관리자 2명은 동등한 권한의 사전 발급 ID·비밀번호 계정을 사용한다. 공개 관리자 가입 기능은 제공하지 않는다.
- 상품 삭제는 숨김 처리로 과거 주문과 관계를 보존한다. 판매 여부·순서·재고·할인 대상을 관리한다.
- 관리자 인증과 비회원 주문에 이어 카카오·태블릿 회원 인증과 회원 주문 연결을 구현한다. 회원 주문 내역·저장 배송지 화면은 후속 단계다.
- Supabase는 신규 프로젝트로 준비한다. 코드 구현과 격리된 테스트 DB 검증은 원격 프로젝트 적용·인증 검증과 구분해 기록한다.
