# 주문 안내: 알리고 알림톡

접수는 결제주문당 1회, 실제 발송 완료는 배송지별 보내는 분에게 1회 안내한다. 엑셀 출력·송장번호 저장만으로는 보내지 않는다. 주문 처리와 알림 발송은 분리하며 알림 장애로 주문을 실패시키지 않는다.

최신 사용자 결정(2026-10-07)에 따라 **접수·발송 알림톡 모두 보내는 분에게만** 보낸다. 받는 분 이름은 발송 본문에 표시하지만 받는 분 전화번호로는 보내지 않는다. 기존 받는 분 대상 대기·실패 작업은 제외하고 재시도하지 않는다. 이미 보낸 이력은 유지하며 전송 중 외부 서비스에 접수된 메시지는 회수할 수 없다.

## 알리고 적용 순서

1. API Key, 사용자 ID, 채널 발신프로필 키(senderkey), 인증한 발신번호를 준비한다. 키는 채팅·Git·브라우저 코드에 넣지 않는다.
2. 사용자가 직접 Supabase SQL Editor에서 `202610060001_aligo_notifications.sql` → `202610070001_sender_only_notifications.sql` → `202610100001_aligo_only_notifications.sql` 순서로 아직 적용하지 않은 파일 전체를 실행한다(`supabase/migrations/`). 마지막 파일은 이전 문자 발송을 중지하고 알리고만 허용한다. 기존 알리고 켜짐·테스트 설정은 유지하며 이전 문자 연결이었다면 알리고 꺼짐·테스트 모드로 전환한다. 주문·상품·기존 알림 이력은 보존하며 SQL 자체는 발송하지 않는다.
3. `.env.local` 또는 Vercel 서버 환경변수를 설정한다. Preview에서는 실제 발송을 켜지 않는다.

```dotenv
ALIGO_ENABLED=true
ALIGO_API_KEY=발급받은_API_키
ALIGO_USER_ID=알리고_사용자_ID
ALIGO_SENDER_KEY=채널_발신프로필_키
ALIGO_SENDER_NUMBER=등록한_발신번호_숫자만
ALIGO_ORDER_TEMPLATE_CODE=UM_0746
ALIGO_SHIPPING_TEMPLATE_CODE=UM_0737
ALIGO_TEST_MODE=true
# Fixie에서 복사한 인증정보 포함 HTTP/HTTPS 프록시 URL
FIXIE_URL=
```

4. `npm run aligo:check`로 인증·템플릿 조회를 확인한다. 템플릿만 읽고 DB 설정 변경·메시지 전송은 하지 않는다. `ALIGO_ENABLED=false`여도 읽기 확인은 가능하다. 키는 출력하지 않는다.
5. 로컬 서버 재시작 또는 Vercel 재배포 후 관리자 **알림 내역 → 연결 확인**을 실행한다. 승인 상태와 등록 정보를 확인하며 메시지는 발송하지 않는다.
6. **알림 켜기** 또는 **새 연결 적용**을 선택한다. 기본 테스트 모드에서는 새 주문의 API 요청만 테스트하며 고객에게 보내지 않는다. 테스트 건은 나중에 실발송으로 다시 보내지 않는다.
7. 두 템플릿이 검수 승인되고 사용 중단 상태가 아닌지 확인한 뒤 `ALIGO_TEST_MODE=false`로 변경·재배포한다(로컬은 서버 재시작). **새 연결 적용** 후 보내는 분에 본인 번호를 입력해 새 주문·발송의 실수신을 확인한다. `ALIGO_SENDER_NUMBER`는 등록 발신번호이며 수신번호를 지정하는 설정이 아니다. 이는 유료 실발송이며 구현·격리 테스트 과정에서 자동 실행하지 않는다.

환경변수와 DB의 공급자·테스트 여부가 일치할 때만 해당 작업을 전송한다. 예를 들어 로컬 알리고 테스트와 운영 알리고 실발송가 같은 DB 작업을 가져가지 못하도록 작업에도 공급자·모드를 기록한다. 연결 전환 시 이전 연결의 대기 건은 제외하고 전송 중인 건이 있으면 전환을 막는다. 과거 건은 다시 보내지 않는다.

`ALIGO_ENABLED=false`는 해당 서버의 외부 발송을 막는다. 관리자 **알림 끄기**는 DB 전체의 신규 알림 생성과 대기 작업을 중지한다. 이미 외부 전송 중인 메시지는 취소할 수 없다. 로컬·운영이 같은 DB를 쓰면 관리자 설정을 공유한다.

## 템플릿과 내용

- 접수 `UM_0746`: 주문번호·배송지수·주문금액·배송지정보.
- 발송 `UM_0737`: 보내는분·받는분·발송상품.
- 사용자가 전달한 강조 타이틀은 ‘주문 접수가 완료되었습니다.’ / ‘상품이 발송되었습니다.’, 보조 문구는 ‘나무와열매’다. **알리고에 저장된 최종 등록본을 API로 읽어 사용하며 추정한 줄바꿈을 고정하지 않는다.**
- 본문·강조 타이틀·등록 버튼을 치환하며 보조 문구·이미지는 등록 템플릿 설정을 따른다. 실발송은 `inspStatus=APR`이며 `status=A` 또는 `R`인 템플릿을 허용하고 `S`는 차단한다. 승인과 사용 상태는 별개다. 조회 실패는 작업 선점 전에 중단해 대기 건을 소모하지 않는다. 템플릿 목록을 한 번에 조회하고 서버 인스턴스별 메모리에서 5분간 재사용한다. 동시에 시작한 일반 조회도 합친다. ‘연결 확인/새 연결 적용’과 CLI는 최신 템플릿을 조회하며 실패한 응답·기한이 지난 응답은 재사용하지 않는다. 계정·템플릿·테스트 모드·프록시가 바뀌면 새로 조회한다. 콜드 스타트·다른 인스턴스 사이의 캐시는 공유하지 않는다.
- 상태 해석 근거: [알리고 API](https://smartsms.aligo.in/alimapi.html)는 `APR`(승인)과 `R`(대기)을 구분하며, 같은 알림톡 상태 체계를 설명하는 [핑거푸시 공식 가이드](https://developers.fingerpush.com/alimtalk-cj/alimtalk-manual-2)는 `R`을 발송 전, `A`를 한 번 이상 발송된 상태로 설명한다. 실제 등록본이 `APR + R`로 조회되는 것과 함께 판단해 첫 발송을 앱에서 막지 않는다. 최종 발송 접수·수신 성공은 실제 알리고 응답/결과로 별도 확인한다.
- 배송지정보는 순번별 수령인 이름·배송주소·상세주소·상품명·수량이다. 휴대폰 번호는 본문에 넣지 않는다. 발송상품은 해당 배송지의 상품명·수량이다. 주문 당시 스냅샷을 사용하고 기존 체험상품의 임시 과일·중량 접두어를 제거한다.
- 본문 1,000자·강조 타이틀 28자 초과, 알 수 없는 변수는 실패로 남긴다. 주소·주문정보를 임의로 자르지 않는다. 많은 배송지 주문의 요약 정책은 별도 합의 사항이다.
- 대체문자는 `failover=N`으로 꺼져 있다. 문자 발송 기능은 제공하지 않는다.
- 전송 직전 완성 본문·템플릿 코드·타이틀·버튼을 DB에 저장해 등록본이 바뀌어도 과거 발송 내용을 유지한다.

[알리고 공식 API](https://smartsms.aligo.in/alimapi.html): 템플릿 조회는 `/akv10/template/list/`, 전송은 `/akv10/alimtalk/send/`를 사용한다. 테스트는 `testMode=Y`, 실제 발송은 `N`이다.

## Fixie 연결과 Vercel

알리고의 로그인 ID가 `ALIGO_USER_ID`다. 로컬 PC와 Vercel의 발신 IP는 별개이고 기본 Vercel 발신 IP는 변동된다. 이번 연결은 알리고 API 요청에만 Fixie 고정 IP를 사용한다. Supabase 등 다른 요청은 이 프록시를 사용하지 않는다.

1. [Fixie Vercel 연동 안내](https://usefixie.com/documentation/vercel)를 따라 **HTTP/HTTPS** 프록시를 생성한다. SOCKS 전용 주소는 지원하지 않는다. 지역은 Vercel 함수와 가까운 곳을 선택한다.
2. Fixie 대시보드의 **고정 IP 두 개 모두** 알리고 ‘발송 서버 IP’에 등록한다. PC IP·도메인 IP·프록시 URL을 해당 IP 칸에 넣지 않는다.
3. 인증정보가 포함된 Fixie 프록시 URL 전체를 `.env.local`과 Vercel Project → Settings → Environment Variables의 `FIXIE_URL`에 각각 설정한다. 연동 앱이 자동 생성했다면 값의 존재와 적용 환경만 확인한다. URL에는 비밀번호가 있으므로 화면 공유·로그·Git·`NEXT_PUBLIC_*`에 노출하지 않는다.
4. Vercel에는 기존 `ALIGO_*`, `ALIGO_ENABLED=true`, `ALIGO_TEST_MODE=true`도 설정한다. 환경변수 변경 후 재배포가 필요하다. Node.js 런타임(권장 22.x 이상)을 사용한다.
5. 로컬 `npm run aligo:check`의 연결 경로가 **Fixie 고정 IP**인지 확인하고 템플릿 조회 성공을 확인한다. 이 명령은 메시지를 보내지 않는다. 배포 후 관리자 ‘연결 확인’으로 Vercel에서도 확인한다.

Vercel(`VERCEL=1`)에서는 알리고 연결에 `FIXIE_URL`이 필수다. 로컬에서 비워두면 로컬 공인 IP로 직접 연결하므로 해당 IP도 알리고에 등록되어 있어야 한다. 잘못된 URL·프록시 장애 때 직접 연결로 우회하지 않으며 프록시 인증정보와 API 원문 오류를 노출하지 않는다. HTTPS CONNECT 터널을 사용하며 TLS 인증서 검증을 유지한다.

2026-10-07 확인 기준 Fixie HTTP/HTTPS 무료 플랜은 월 **500회 요청 / 100MB**다. 알림톡 요금은 별도다. 템플릿 조회·연결 확인·테스트 요청도 한도에 포함되므로 500회는 주문 500건이 아니다. 하루 수십~수백 주문을 받는 운영에서는 무료 한도가 부족할 수 있다. [최신 Fixie 요금표](https://usefixie.com/pricing)에서 확인하며 유료 전환·서비스 가입은 자동 수행하지 않는다.

대기 작업이 없는 자동 처리에서는 외부 API를 호출하지 않는다. 템플릿 조회는 한 요청으로 합치고 위의 5분 캐시를 사용하지만 전체 월 요청 수를 보장하지 않는다. 한도/연결 오류로 발송 결과가 불명확하면 자동 재발송하지 않고 알리고에서 실제 접수 여부를 확인한다.

참고: [Fixie HTTPS 연결](https://usefixie.com/documentation/http-and-https-requests), [Vercel 발신 IP](https://vercel.com/kb/guide/how-to-allowlist-deployment-ip-address). Vercel 자체 요금제의 상업적 이용 조건은 Fixie 이용료와 별개다.

## 내역과 재시도

| 상태 | 의미 |
| --- | --- |
| 발송 대기 | 외부 요청 전. 주문·발송 후 자동 처리 대상 |
| 처리 중 | 서버가 선점한 작업 |
| 알리고 접수 완료 | 알리고가 요청을 접수함. 고객 수신 완료와 다름 |
| 이전 문자 접수 완료 | 보존된 이전 문자 이력. 재발송 불가 |
| 테스트 완료 · 미발송 | 테스트만 처리. 실발송으로 재시도하지 않음 |
| 접수 실패 | 명확한 거절·사전 검증 실패. 원인 해결 후 같은 연결에서 재시도 가능 |
| 결과 확인 필요 | 시간 초과·응답 이상. 중복 방지를 위해 재시도하지 않음 |
| 발송 제외 | 비활성화·취소·연결 전환으로 보내지 않음 |

알리고 `code`와 `info.mid`를 결과 코드·메시지 ID로 저장한다. 최종 수신 여부는 알리고 전송결과에서 조회한다. 수신결과 API/웹훅 자동 동기화는 이번 범위에 포함하지 않았다. 원문 API 오류·키를 로그에 남기지 않는다.

요청은 한 번만 수행한다. 결과 저장 전 서버가 종료된 ‘처리 중’ 작업은 5분 후 다음 처리·연결 설정 시 ‘결과 확인 필요’로 바뀐다. 공급자에서 실제 접수 여부를 먼저 확인한다. 알림만 다시 보내려고 주문을 재접수하지 않는다.

## 자동 처리와 이전 문자 기능 정리

주문 접수·발송 완료 응답 후 Next.js `after`에서 내부 대기열을 처리한다. 중복 방지와 주문/발송 원자성을 위해 내부 대기열은 유지한다. 템플릿 조회 실패 등으로 남은 대기 작업은 다음 주문 접수·발송 완료·알림톡 실패 건별 재시도가 시작하는 자동 처리에서 다시 확인한다. 이들 이벤트가 없으면 별도의 정기 처리는 실행되지 않는다.

사용자 요청(2026-10-10)으로 **대기 알림 처리** 버튼과 관리자 일괄 처리 API, 외부 스케줄러용 처리 API를 제거했다. 실패한 알림톡의 개별 **재시도**는 유지하지만 결과가 불명확한 작업·이전 문자 이력·받는 분 대상 이력은 재시도하지 않는다.

SOLAPI 어댑터·문자 본문 생성·공급자 선택을 제거했다. 이전 마이그레이션은 설치 이력을 위해 유지한다. 새 SQL은 이전 문자 대기/실패 작업을 제외하고 처리 중이던 작업을 결과 확인 필요로 전환한다. 저장된 과거 본문·메시지 ID는 조회용으로 보존한다.

기존 설치에서는 로컬과 Vercel의 발송 게이트를 `ALIGO_ENABLED`로 옮긴다. 기존에 켜두었다면 `ALIGO_ENABLED=true`, 꺼두었다면 `false`를 사용한다. `SMS_ENABLED`, `NOTIFICATION_PROVIDER`, `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_SENDER_NUMBER`, `NOTIFICATION_CRON_SECRET`는 더 이상 사용하지 않으므로 삭제한다. 외부에서 기존 `/api/notifications/process` 호출을 등록했다면 해당 스케줄도 삭제한다. Vercel 변경은 재배포 후 적용된다.

구현: `messages.ts`(템플릿 변수), `aligo.ts`(발송), `aligo-transport.ts`(Fixie 연결), `dispatch.ts`(내부 작업 처리), `server.ts`(환경·DB). SQL은 별도 파일로 제공하며 사용자가 직접 실행한다.
