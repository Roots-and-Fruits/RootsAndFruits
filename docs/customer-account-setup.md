# 개인 회원 마이페이지 적용

## DB 적용

`202610110001_reorder_kind.sql`까지 적용한 Supabase 프로젝트에서 `supabase/migrations/202610110002_customer_account.sql` 전체를 직접 실행합니다. 원격 DB에 자동 실행하지 않습니다.

주소록·기본 보내는 분 테이블과 회원 조회/저장 함수를 추가합니다. 기존 주문, 송장, 상품, 회원 연결, 알림 설정은 변경하지 않으며 메시지를 발송하지 않습니다. 재실행 시 저장된 회원 정보를 삭제하지 않습니다. 앱 배포 전 SQL을 적용합니다. 회원 탈퇴를 제공하려면 아래 추가 SQL과 KAKAO_ADMIN_KEY 설정도 필요합니다.

## 고객 기능

- 비회원이 홈에서 상품 구매·체험 과일 보내기를 누르면 로그인 안내창이 표시됩니다. 카카오 로그인 후 선택한 주문 화면으로 돌아오거나 ‘비회원으로 계속하기’로 기존 작성 내용을 확인합니다. 닫으면 홈으로 돌아가고 입력은 유지합니다. 로그인된 카카오·태블릿 회원 및 미리보기에는 표시하지 않으며, 주문 중 새로고침에는 다시 묻지 않습니다. 관리자 로그인만 있는 경우에는 고객 로그인으로 보지 않아 안내창을 표시합니다.
- 헤더의 **마이페이지** → `/account/orders`: 로그인 계정이 직접 접수한 원본 주문을 최신순 20건씩 표시하고 이전 주문 더 보기를 제공합니다. 취소 주문도 표시합니다.
- 주문 상세: 보내는 분, 배송지별 수령인·주소·상품·금액·출발 예정일·발송 상태와 등록된 모든 송장번호를 표시합니다. 번호는 롯데택배 조회 링크입니다. 내부 출력 상태는 ‘발송 준비 중’으로 표시하며 배송 도착 여부를 추정하지 않습니다.
- `/account/addresses`: 배송지 등록·수정·삭제, 기본 배송지 지정. 기본은 최대 한 곳이며 삭제 시 다른 주소를 임의로 기본 지정하지 않습니다.
- `/account/sender`: 기본 보내는 분 이름·휴대폰 한 세트. 새 주문에만 채우고 기존 입력·접수 내역은 변경하지 않습니다. 주문 중 보내는 분을 수정해도 기본값은 유지합니다. 동의 항목을 자동 선택하지 않습니다.
- 일반/체험 주문의 받는 분·주소 단계와 통합 수정에서 주소록을 선택합니다. 주소 단계와 통합 수정에서는 배송지 저장도 제공합니다. 주소록 저장은 주문 접수와 별도 동작이며 자동으로 모든 배송지를 수집하지 않습니다.
- 관리자 수정·재주문과 비회원·태블릿 주문은 고객 내역에 연결하지 않습니다. 전화번호가 같아도 본인 주문으로 추정하지 않습니다. 고객용 수정·취소·재주문 기능은 없습니다.

## 권한과 API

카카오 개인 회원만 회원 API를 사용할 수 있습니다. 서버 인증에서 확인한 회원 ID를 전달하고 DB 함수에서도 계정 구분과 소유권을 확인합니다. 새 테이블은 RLS를 켜고 직접 테이블 접근을 차단합니다. 공개/일반 인증 사용자는 회원 RPC를 직접 실행할 수 없고 서버 서비스 역할만 실행합니다.

- `GET /api/account/preferences`: 기본 보내는 분과 주소록
- `PUT /api/account/sender`: 이름·전화번호 저장
- `PUT /api/account/addresses/{uuid}`: 배송지 등록·수정. 같은 UUID 재시도는 새 배송지를 중복 생성하지 않음
- `DELETE /api/account/addresses/{uuid}`: 본인 주소록에서 삭제
- `GET /api/account/orders?before={주문번호}`: 내 원본 주문 목록
- `GET /api/account/orders/{uuid}`: 본인 원본 주문 상세. 다른 회원·관리자 재접수는 404

읽기/쓰기와 오류 응답은 `private, no-store`입니다. 고객 DTO는 허용한 필드만 구성하며 관리자 메모·요청 원문·내부 이력·회원 ID·동의 이력을 포함하지 않습니다. 변경 요청은 같은 출처인지 검사합니다. 서버에서 소유권을 확인하므로 클라이언트에서 회원 ID를 바꿔 접근할 수 없습니다.

## 로그인 시 초기화

카카오/태블릿 로그인·고객 로그아웃 성공 시 비밀정보가 없는 세대 쿠키 `rf-customer-epoch`를 교체합니다. 브라우저는 주문 임시 입력·접수 결과 미확인 요청·완료 정보를 정리하고 다른 탭에도 반영합니다. 계정 전환 전 요청의 응답은 이후 화면에 반영하지 않습니다. 이 쿠키는 인증이나 권한 부여에 쓰지 않습니다.

로그인 실패·취소, 같은 세션에서 새로고침, 자동 세션 갱신은 초기화하지 않습니다. 일반/체험과 미리보기 입력은 정리하지만 Supabase 인증 저장소와 관리자 재접수 저장소를 통째로 삭제하지 않습니다. 저장소 삭제 실패 시 이전 입력을 노출하지 않고 사이트 저장 데이터 정리를 안내합니다.

결과 미확인 요청이 삭제되면 재접수 전에 내 주문 내역 또는 카운터 확인을 안내합니다. 이름·주소·요청 식별자는 남기지 않고 안내 표시 여부만 저장하며 ‘확인했어요’로 닫습니다. 서버에 저장된 주문은 취소하거나 삭제하지 않습니다.

## 확인 절차

카카오 계정으로 로그인해 기본 보내는 분과 주소록을 저장한 뒤 새 주문에서 불러옵니다. 주문 입력 수정이 주소록/기본값을 바꾸지 않는지 확인합니다. 기존 회원 주문·취소 상태·여러 송장번호와 링크를 확인하고, 로그아웃/다른 계정 로그인 및 다른 탭·뒤로 가기에서 이전 입력이 나타나지 않는지 확인합니다.

격리된 DB 테스트와 브라우저 테스트는 실제 카카오 계정이나 실발송을 사용하지 않습니다. 실제 Supabase SQL 적용과 카카오 로그인은 운영 설정에서 별도로 확인합니다.

## 계정 관리·탈퇴 추가 적용 (2026-10-11)

1. `202610110002_customer_account.sql` 적용 후 `supabase/migrations/202610110004_customer_deletion.sql`을 직접 실행합니다. 설치 시 계정·주문을 삭제하거나 메시지를 보내지 않습니다. 원격 DB는 에이전트가 실행하지 않습니다.
2. 로그인에 사용하는 카카오디벨로퍼스 앱의 Admin 키를 서버 전용 `KAKAO_ADMIN_KEY`에 저장합니다. 로컬 `.env.local` 및 배포 시 Vercel Secret으로 등록하고 서버 재시작/재배포로 반영합니다. `NEXT_PUBLIC_*`에 넣지 않습니다. 알리고 발송 키와 다른 값입니다.
3. `/account/settings`에서 로그인 방식과 계정 삭제 안내를 제공합니다. 키 또는 SQL이 준비되지 않으면 삭제 버튼은 비활성 상태입니다. 확인창에서 삭제 대상과 기존 주문 유지에 동의해야 실행됩니다.

서버가 확인한 현재 카카오 회원의 provider ID로 [카카오 연결 해제 API](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api#unlink)를 호출한 뒤 [Supabase Auth 계정 삭제](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser)를 요청합니다. 외부 응답 실패를 완료로 처리하지 않으며, 이미 연결 해제된 재시도 응답(-101)은 처리할 수 있습니다. Auth 삭제 실패는 같은 화면에서 재시도합니다. Admin 키는 로그인 앱의 키여야 합니다.

추가 SQL은 Auth 계정 삭제 트랜잭션에서 주문 회원 연결을 해제하는 트리거를 설치합니다. 주문의 접수 구분·수령인·금액·배송·송장·알림은 유지하고 `member_deleted_at`만 기록합니다. 기존 CASCADE로 주소록·기본 보내는 분을 지웁니다. 실패하면 Auth 삭제와 주문 연결 변경도 함께 롤백됩니다. 기존 계정이나 회원 데이터를 소급 삭제하지 않습니다.

`GET /api/account/settings`는 삭제 기능 준비 여부만 제공하고, `DELETE /api/account/membership`은 본인 계정만 삭제합니다. 임의 회원 ID 입력은 허용하지 않습니다. 관리자·태블릿·비회원은 이용할 수 없습니다. 탈퇴 후 재가입은 신규 계정이며 과거 주문은 연결하지 않습니다.

로그인·로그아웃·마이페이지 버튼은 헤더에만 있습니다. 로그인된 고객은 `/login`에서 별도 버튼 안내 화면 없이 마이페이지/복귀 화면으로 이동합니다. 명시적 로그아웃은 Supabase 세션과 남은 쿠키를 함께 정리하고, 비회원 주문은 로그인 안내에서 ‘비회원으로 계속하기’를 선택해 진행합니다.
